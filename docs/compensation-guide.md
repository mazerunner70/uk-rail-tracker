# Compensation Guide

UK Delay Repay rules by train operating company. Used by M4 to estimate compensation and flag claimable journeys.

> **Disclaimer**: Delay Repay schemes change. Thresholds and percentages below are approximate as of August 2026. Always verify on the operator's website before submitting a claim. This app provides estimates, not guarantees.

## How Delay Repay works

1. Your train is **delayed** arriving at your destination or **cancelled**
2. The delay meets the operator's **minimum threshold** (typically 15, 30, or 60 minutes)
3. You claim within the operator's **time window** (usually 28–56 days)
4. You receive a **percentage of your fare** (or season ticket pro-rata) as cash, voucher, or e-wallet credit

## Standard compensation tiers

Most operators use a three-tier structure:

| Delay at destination | Typical compensation |
|--------------------|---------------------|
| 15–29 minutes | 25% of single fare |
| 30–59 minutes | 50% of single fare |
| 60+ minutes | 100% of single fare |
| Cancelled (take alternative or abandon) | 50–100% depending on operator |

Some operators use enhanced schemes with lower thresholds (15 min) or additional tiers.

## Season ticket pro-rata

For season ticket holders, compensation is calculated as a proportion of the daily cost:

```
daily_rate = season_ticket_price / number_of_valid_days
compensation = daily_rate × compensation_percentage
```

Example: £5,000 annual season (230 valid days), 60 min delay (100%):

```
daily_rate = £5,000 / 230 = £21.74
compensation = £21.74 × 100% = £21.74
```

The app should support an optional season ticket price in Settings for pro-rata calculations (M4.1).

## App rules engine design

Store operator rules as a JSON config bundled in the app (easy to update without code changes):

```json
{
  "operators": [
    {
      "code": "GW",
      "name": "Great Western Railway",
      "minDelayMinutes": 30,
      "tiers": [
        { "minMinutes": 30, "maxMinutes": 59, "percentage": 50 },
        { "minMinutes": 60, "maxMinutes": null, "percentage": 100 }
      ],
      "cancelledPercentage": 100,
      "claimWindowDays": 56,
      "claimUrl": "https://www.gwr.com/help-and-support/refunds-and-compensation/delay-repay"
    }
  ]
}
```

### Eligibility check (pseudocode)

```kotlin
fun isClaimable(journey: JourneyLog, operator: OperatorRules): ClaimResult {
    if (journey.wasCancelled) {
        return ClaimResult(operator.cancelledPercentage, operator.claimUrl)
    }
    val tier = operator.tiers
        .filter { journey.delayMinutes >= it.minMinutes }
        .maxByOrNull { it.minMinutes }
        ?: return ClaimResult.NOT_ELIGIBLE
    if (journey.delayMinutes < operator.minDelayMinutes) {
        return ClaimResult.NOT_ELIGIBLE
    }
    val age = daysSince(journey.date)
    if (age > operator.claimWindowDays) {
        return ClaimResult.EXPIRED
    }
    return ClaimResult(tier.percentage, operator.claimUrl)
}
```

## What the app logs for claims

When a journey completes (M3 → M4), record:

| Field | Source | Needed for claim? |
|-------|--------|-------------------|
| Date of travel | Journey start | Yes |
| Origin station | User selection | Yes |
| Destination station | User selection | Yes |
| Scheduled departure time | API / timetable | Yes |
| Scheduled arrival time | API / timetable | Yes |
| Actual arrival time | API (final calling point) | Yes |
| Delay in minutes | Calculated | Yes |
| Cancelled? | API status | Yes |
| Operator | Station data / service | Yes (determines rules) |
| Ticket type | User input (optional) | Yes (for amount) |
| Ticket price | User input (optional) | Yes (for amount) |

Most operator claim forms also ask for ticket photo/upload — the app cannot provide this automatically.

## Claim assist features (M4)

1. **Inbox**: List claimable journeys sorted by estimated refund amount
2. **Estimate**: Show "Estimated refund: £X.XX (50% of £Y.YY single fare)"
3. **Deep link**: Open operator claim portal in browser
4. **Pre-fill**: Copy journey details to clipboard for pasting into claim form
5. **Export**: CSV with all claimable journeys for the period
6. **Reminder**: Notification when a claim is approaching its expiry window (M5)

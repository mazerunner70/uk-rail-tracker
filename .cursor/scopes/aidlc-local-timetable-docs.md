# local-timetable-docs scope

Minimal documentation pass. Capture the intent, bound the two pages, then write them from the existing proofs of concept. No code, tests, or deployment.

Guard Policy is relaxed: a later edit to an approved input is recorded and announced, and the writing continues. The approval questions themselves remain.

## Why these stages, why skip those

The deliverable is two markdown files that can be finished in about an hour. Initialization, intent capture, scope definition, and requirements analysis are enough to frame the future intent and write the service page. Market research, design, code, test, and operations are skipped because this pass does not build or ship the service.
